**本机完整业务环境已于 2026-09-23 跑通：真实 MySQL、Redis、Nacos、认证、网关和 Vue 页面均已接通，并完成实际登录及报价试算。** 当前业务入口为 http://127.0.0.1:8888/；Nacos 控制台仍为 http://127.0.0.1:18080/。

## 0. 本机启动与登录

1. 双击 D:\pig\启动报价系统.cmd。脚本按顺序启动 Redis、注册中心、报价后端、认证、网关和前端，并打开浏览器。已经监听对应端口的服务会复用，不必在 IDE 中重复启动。
2. 登录账号为 **admin**；本次生成的初始密码保存在 [本机初始密码](../work/local/pig-admin-password.txt)。这是 pig 业务账号，区别于 Nacos 的 nacos 账号。按登录页提示完成文字点选验证码。
3. 登录后选择 **报价管理 → 报价工作台**。本机已有指标及历史报价，无需重新导入 SQL 或初始化基价。
4. 用完可双击 D:\pig\停止报价系统.cmd。停止脚本只处理启动脚本创建且身份一致的进程；你在 IDE 中启动的 Nacos 需在 IDE 中停止。

本机数据库用途：pig_config 存 Nacos 配置，pig 存账号、角色、菜单，quotationsystem 存 6 张报价业务表。现有报价数据保留；不要互换这三个库名。

Redis 安装在 work/local/redis-8.10.2，数据写入 work/local/redis-data，仅监听 127.0.0.1:6379。服务日志位于 work/local/logs。work/local 已被 Git 忽略，包含本机密码、运行数据和验证会话，不应打包发布。

启动脚本使用当前 PATH 中的 Java、Node；已用 JDK 21 和 Node 24 在本机验证。修改 Java 代码后，先停止脚本启动的服务，再在项目根目录执行以下命令重建并启动：

```powershell
.\scripts\Stop-Local.ps1
.\scripts\Start-Local.ps1 -Build
```

仅修改 Vue 页面时会自动热更新。脚本从现有注册中心配置读取本机 MySQL 凭据，通过各子进程环境变量传入；不会把密码写进脚本，也不修改全局系统环境变量。

## 1. 菜单放在哪里

新增一级菜单 **报价管理**，与系统管理并列，避免把日常业务放进系统配置菜单。

| 子菜单 | 用途 |
|---|---|
| 报价工作台 | 导入清单、手工建单、补充参数、试算、导出 |

### 统一导入、逐行识别报价（2026-09-24 更新）

现在不再选择整单属于风管还是设备。流程是：**导入客户清单 → 按行识别材料／设备 → 每行匹配对应规则 → 计算行报价 → 汇总整单**。

- 点击「导入客户清单」，上传 Excel，系统分别识别每个工作表的表头，点击「确认导入并创建报价」后按原工作表顺序合并为一单。同一文件中的「设备」「风管、风阀、风口」无需二选一，同一表也可混排不同产品。
- 导入页默认展示名称、规格参数、数量／工程量、单位、备注这五个常用字段，并自动匹配「规格参数」「技术参数」及带换行、全角单位的常见表头。只有风管时显示风管参数，只有设备时显示设备参数，混合清单分组展示；共用列只映射一次。
- 已匹配的独立参数列自动显示；其他字段默认收起，点击各组「补充独立列」调整。规格文本中的尺寸、厚度或工况无需重复映射到独立列。「起始行与其他设置」中仍可调整起始行、显示其他类型参数或排除说明页。
- 核对下方前五条产品预览，尤其是规格和数量；不确定的列保留提示，不会强行猜测。明确的楼层、区域标题和说明单独保存在来源记录中，不作为产品报价；无法识别的真实产品仍保留待确认。
- 此次是导入识别和界面优化，没有接入大模型或改变计算公式。旧报价不会自动重写；要使用新识别结果，请重新导入原文件创建草稿。导入页「设备」是用于展示参数的范围分组，具体产品规则、选型及能否报价仍在报价工作台核对。
- 已识别表头的工作表默认直接导入；需要核对时展开该表，单独调整起始行与列映射。非空但无法识别表头的表会展开提示，不能静默漏掉；封面、说明页可勾选不参与报价并填写原因，空白表自动跳过。
- 导入后可查看「整份文件导入情况」，每行「参数／明细 → 原始客户清单内容」保留来源工作表和原行号。旧版只导入一个工作表的草稿不会自动补入其余表，需重新导入整份文件建立新报价；「重新识别清单」只处理草稿中已有的行。
- 共用的「工程量」或「数量」列只映射一次，系统根据单位读取面积或设备数量；如果确有两列独立数量，再分别映射。不确定的表头不猜测，需要你确认。
- 导入后查看「识别类别」及风管／设备／待识别项数。每行根据名称、规格和已发布指标分别计算；未知材料、缺规格、缺成本或风机多候选会明确提示待确认，不能当作零价生成正式报价。
- 明确含税、付款、是否安装等报价条件，再点击「保存并试算」。只有涉及风管时才显示风管默认条件；纯风管清单不要求发布设备指标。
- 「整单供货条件」中的 **整单是否含运费** 是唯一运费开关，同时作用于清单内风管、设备等所有行。选择含运费后，各行按原有运费规则计算；切回不含运费后，各行都不再计运费。设备行已填的每台／每个运费会保留，方便再次选择含运费时使用。
- 旧草稿如果原来风管、设备运费选择不一致，会显示待确认，需要重新选择一次整单运费口径；不会自动取其中一个。历史正式报价及已导出文件保留原样，修改先创建修订版。
- 已有草稿可直接点击「重新识别清单」，不用重新上传。保留原始行、来源、数量、已填参数和安装条件；清除旧试算结果后重新计算。旧草稿误带的「风管」类别会按名称重识别，其他明确指定类别保留。已定稿版本先创建修订版。
- 手工建单统一用「新建报价」，保存时同样识别每行。未知项目需要补充名称、规格或明确类别，不能匹配规则时仍保留待确认。

### 设备行计价与整单汇总

1. 用报价负责人账号进入 **报价管理 → 指标管理 → 设备指标**，点击「从已核对源表建立草稿」。在原有子页签中维护供货价格、运费与付款、材料电机及外购价格、成本公式和设备参数。核对后依次「保存草稿」「校验指标」「发布指标」，发布后用于新试算；风管、设备和安装分别维护指标版本。
2. 回到 **报价工作台**，点击「导入客户清单」或「新建报价」。系统自动识别每行，不再选择整单类型；导入时合并文件内所有清单工作表，必要时展开各表核对起始行、数量、单位及型号列。未知项目保留待确认；备注、合计和明确配件汇总可在「查看导入时提取的汇总行和备注」核对，重复配件汇总需先明确后才能导入。
3. 在「整单供货条件」明确含税口径、付款方式及「整单是否含运费」。选择含运费且清单涉及设备时，填写送货省区；设备行付款前、未加运费供货金额低于 8,000 元时，在行参数中填写「每台／每个运费」，明确填 0 有效。门槛仍按各设备行判断。
4. 设备行填写名称、规格、数量和客户单位，打开「参数／明细」核对自动识别或手工补充的数据。风机功率、风量、风压等参数可分别填写；双速功率用 `/` 分隔，并按要求补充高低档工况。多候选时由报价员明确选择，不会自动借用相近电机价格。
5. 同一张清单中，类别为「风管」的行填写工程量总面积；其他设备填写数量和单位。含税口径、付款方式和是否含运费均为整单设置。风管、设备使用各自已有价格及运费规则；风管单价／金额保留 1 位小数，设备单价／金额向上取整到元，再汇总整单。
6. 点击「保存并试算」。待确认行不会计入已确定小计，并阻止正式导出；可导出草稿继续核对。全部确认后导出正式报价，不含安装使用单层材料模板，含安装使用带安装模板，风机对客规格使用实际选型型号、功率和工况。客户文件不包含内部成本及公式。

快速试算：设备指标使用随项目提供的原始草稿；新增「防火阀」，规格 `500×500`，数量 `2`、单位「个」，现金、不含税、不含运费，其他参数留空。对应原 Python 的单价为 **126 元**、金额 **252 元**。指标调价后结果会随生效版本变化。

目前设备类对齐范围为风机、各类风阀、百叶风口、消声器／静压箱／接管箱、消声弯头和外购设备供货。**安装费用已独立接入，详见安装模块使用指南**；缺失价格、双速配对数据或未确认规格继续提示待确认。

## 3. 首次使用：负责人发布指标

本机已有正式指标，可直接查看使用。只有新环境没有指标时，才进入 **指标管理 → 初始化基价草稿**；初始化内容来自你提供的《产品基价.xlsx》及已确认规则，初始状态为草稿。

依次核对：

- 板材基价：40g/80g 镀锌板、201/304 不锈钢，包含已确认的 2mm 规格。
- 角钢法兰：规格、计算档位、吨价和每米加工费。
- 加工费与系数：净面积、合口、打孔、配件、运费和税费。
- 付款方案：不含安装 5 种，含安装 3 种。
- 生效日期、指标来源；有必要时查看高级公式。

高级公式现在逐项显示中文对照，以及英文参数的中文含义、单位和取值来源。英文公式仍用于编辑和计算；中文对照会随草稿输入同步更新。例如 material_price 为板材成本，processing 为加工费，closing 为合口费。公式中的 area_factor 在主体公式阶段固定为 1，真正的开板/净面积系数会在后续统一应用，避免重复乘入。

修改后先 **保存草稿 → 校验指标 → 发布指标**。校验检查结构、数值和公式是否合法，业务价格仍要由负责人核对。

已发布指标不能原地修改。调价时点击 **创建新版本**，保存并发布新草稿。最新版本停用或过期后不会退回旧价格。正式导出前还会检查当前生效指标，变化时要求重新试算。

模板沿用原系统已经确认的双模板。负责人可用「暂停正式导出」开关暂时停止新的正式文件生成，历史文件仍可下载。

## 4. 报价员操作流程

### 导入清单

#### AI整理客户资料并自动建草稿

在报价工作台点击「AI整理资料并建草稿」，可一次上传不规则 `.xlsx`/`.xls` 清单、微信聊天截图或材料图片（PNG、JPEG、GIF、WebP）。服务端使用 DeepSeek `deepseek-flash` 提取产品字段，按正式报价模板样式生成「AI待核验报价单.xlsx」，经现有清单导入器自动创建**未试算**的报价草稿。不同资料中相似或矛盾的行会保留供人工处理，模型不会写入价格。

草稿页可下载待核验报价单和原始资料；报价员逐行核对名称、规格、数量、单位及遗漏项。Excel 校验完成后，在同一草稿点击「导回已校验清单」，上传整份文件并核对修改预览，确认后更新原草稿。再点击「人工核验完成」，才能「保存并试算」。再次修改草稿、回导清单或重新识别清单会撤销核验状态，需要重新确认。模型服务不可用、返回空结果或标准清单导入丢行时，不会创建报价草稿。

备注参与产品识别，原名称和备注仍保留。例如“百叶风口”备注“单层百叶”按单层识别；“常开式百叶”备注“自垂百叶单价”保留常开式产品，单独记录自垂百叶计价口径和原文依据。名称与备注冲突或含否定、待确认条件时，需要人工核对后选择实际类型和计价口径。

AI 待核验报价单的主表保留正式报价模板的原有版式；独立的“人工核对”工作表按主表序号显示“核对原因（原始资料）”及可填写参数，类型提供中文下拉选项。带防火阀或止回阀的风机，需要确认附阀类型、宽高或直径、**每台风机附阀数量**、风机成本是否已含阀。未含阀时，系统分别计算风机和阀门再汇总；已含阀时，必须填写已经核实的整套不含税成本（含阀及适用防爆成本），不再重复增加附阀成本。系统不会根据风机机号猜测阀门尺寸。

可在工作台“参数 / 明细”补齐并保存，也可下载 AI 待核验报价单，在主表修改名称、规格、厚度、工艺、单位、数量和备注，在“人工核对”表补齐参数后，保留整份文件，通过原 AI 草稿的 **导回已校验清单** 更新现有报价。核对参数会自动关联主表，不另计产品行；回导不调用 AI，也不计算报价。请保留原有产品行的数量、顺序、序号和隐藏关联ID，新增材料或取消计价在系统内操作。文件绑定草稿及版本，导出后草稿有修改时应重新下载；较早下载的文件没有回导标识，也需要重新下载。回导前展示逐项变化，格式或关联错误会指出对应行，原客户资料及人工修改记录会保留。单价和金额由人工核验后的系统试算生成；试算后的“导入已完善校对版”用于回导人工价格。

服务端环境变量 `DEEPSEEK_API_KEY` 留空时，此入口会提示尚未配置；填写密钥并重启 `pig-upms-biz` 后启用。`DEEPSEEK_BASE_URL` 默认 `https://api.deepseek.com`。密钥只放在服务器环境或未提交的 `.env` 中。一次最多 8 个文件、合计 24MB，智能识别最多 500 行；较大清单请拆分。原始资料及模型生成的标准清单快照保存在报价导入记录中，仅原报价的可见人员能下载。网关为此入口单独设置 10 分钟超时；如果 Nacos 中的 `pig-gateway-*.yml` 覆盖了本地路由列表，部署时也要在 Nacos 为 `/admin/quotation/ai-imports` 增加相同的专用路由。

在工作台点击 **导入客户清单**，支持 .xlsx 和 .xls。

选择工作表、填写产品数据起始行，并核对列映射。唯一表头会自动建议映射；有歧义的字段保留空白。共用工程量／数量列按单位分派；**风管工程量填写总面积，不是用面积再次乘数量，设备填写台数或个数。** 导入不会使用客户旧报价的单价。

预览原表后点击 **确认映射并创建报价**。原始行内容会保留，可以在「参数 / 明细」中查看。无缓存公式和错误单元格会提示核对；系统不会执行客户文件中的公式。

同列纵向合并的报价备注会向下继承。明确的角码、卡扣、30#/40# 角钢汇总会提取到整单条件；合计及说明行保留在「导入时提取的汇总行和备注」中供复核。

限制为每文件 24MB、解压后 80MB、每表 10,000 行和 80 列；服务器自身若有更小上传限制，以部署配置为准。

### 选择整单条件

明确选择含税口径与付款方式。清单含风管时，还要选择面积口径、成品状态、管件类型、法兰形式；有共板法兰时明确是否打孔。贵州镀锌层默认 40g，可改 80g。清单只含设备时不会显示风管默认条件。

**付款方式必须手动选择，没有默认方案。** 切换「本单包含安装」后需重新选择对应付款方式，在安装报价区域逐项核对项目、数量及未税单价。

需要运费时，将「整单是否含运费」选为「含运费」，对应运费按各行规则进入材料单价，再汇总整单，不额外重复加一次。安装金额独立汇总 ×1.01 向上取整，再与材料合计统一乘一次付款系数，整单向上取整数元。

客户提供了实际角码数量、卡扣米数或整单 30#/40# 角钢米数时，再展开相关输入项填写。未提供的项留空；整单角钢米数不能与行内实际米数同时使用。

### 补充行参数、保存试算

点击每行 **参数 / 明细**，补充厚度、材质、宽高、成品状态、管件类型、法兰规格/档位、实际米数、圆法兰数量等。

优先顺序为：明确的行参数 → 清单描述识别 → 整单默认值。混合法兰可以逐行指定；镀锌与不锈钢混在同一报价时会阻止正式出价，需拆单。

清单行不会静默删除。范围外项目、标题等可标记 **本行不计价**，必须填写原因。公式问题需先核对并补正确值，再勾选已确认。

点击 **保存并试算**。待确认行显示原因，不计入已确定小计；任何阻断项未处理完成时，正式报价按钮不可用。修改后展示的是上一次试算结果，必须重新保存试算才能导出。

### 导出与历史版本

- **可编辑校对版**：允许保留待确认项。材料已经计算、只有安装待确认时，材料单价和材料金额仍会保留，黄色行只需填写该产品的安装费用总额；系统回导时重新计算本行报价。材料本身待确认时，可补齐数量、材料单价／金额和备注。不含安装的报价不会出现安装列。
- 人工补价完成后，回到原报价单点击 **导入已完善校对版**。系统先展示逐项差异，以及材料合计、安装合计和付款前合计；确认回导后，人工金额写回该报价版本。材料单价和材料金额只填一个时，系统会根据数量补算另一个；安装费用按产品行总额填写，不再填写安装单价。
- 回导后若仍有未补全项目，可以继续导出校对版再处理；全部补全且其他整单条件有效时，页面会允许生成正式报价。
- 校对版绑定报价单和修订号。导出后如果原报价已保存、重新试算或修订，旧文件不能继续回导，需要重新导出。旧版本校对文件没有回导标识，也需要重新导出。
- **正式报价**：所有条件满足后才能生成。不含安装使用「单层材料」，含安装使用「带安装」，文件只保留对应工作表及公司 Logo。
- 正式报价生成后，该版本锁定。修改请 **创建修订版**，新版本重新试算，旧文件不变。
- 未导出的草稿可删除；已有导出记录的单据使用归档。恢复后回到归档前状态，定稿不会恢复成可编辑草稿。
- 历史下载返回当时保存的文件，不按现价重新生成。

使用初始化的 V1 指标，不修改价格。新建空白报价，填好客户和项目。

| 项目 | 选择 / 填写 |
|---|---|
| 产品 | 镀锌风管 |
| 厚度 / 尺寸 | 0.75mm / 800×320 |
| 工程量 | 100㎡ |
| 口径 | 净面积、半成品、直管、角钢法兰、40g 镀锌 |

| 付款 | 现金 |
| 配件、实际米数 | 留空 |

预期 **综合单价 42.5 元/㎡、总额 4,250.0 元**。该样例已经在新页面连接真实 Java 业务的隔离环境中跑通，并与 Python 参照单价核对。

再试一次不选择付款方式，系统应提示待确认且不能生成正式报价；正式导出后应锁定 V1，创建 V2 后可继续编辑。

## 6. 配置尚未修好时，临时体验界面

这是验收工具，使用 H2 内存数据库和真实 Java 报价服务；绕过 pig 登录、网关及权限过滤器。仅监听本机，**数据重启即清空，不要录正式业务数据**。

确保前端依赖已安装。在两个 PowerShell 窗口分别执行：

窗口一，临时 Java 验收后端：

    cd D:\pig
    mvn -B -ntp -pl pig-upms/pig-upms-biz -am test '-Dtest=QuotationPreviewTests' '-Dquotation.preview=true' '-Dsurefire.failIfNoSpecifiedTests=false' '-Ddocker.skip=true'

窗口二，临时界面：

    cd D:\pig
    node pig-ui/node_modules/vite/bin/vite.js --config quotation-verification/ui/vite.config.mjs

打开 **http://127.0.0.1:18763**，先到指标管理初始化并发布。临时后端最多运行 45 分钟。结束时可执行下面命令停止临时后端，并在窗口二按 Ctrl+C 停止界面：

    Invoke-WebRequest -UseBasicParsing -Method Post -Uri http://127.0.0.1:18762/__stop
